# Human Gates Implementation Plan

**Goal:** Every step that creates a key, moves devnet SOL, deploys, signs devnet transactions, changes repo visibility or submits the form — each a `human_gate: true` manifest task the orchestrator never dispatches to an executor.
**Architecture:** The gate-concierge runs each gate in its own session on the user's per-gate "continue" (wallet + faucet in the preflight pass that starts when the architect finishes; spike deploy + spike run early in Step 2; the rest in Step 3). The orchestrator pauses at each gate, re-runs the task's read-only gate command itself, commits the declared files, and resumes. The burner is loaded from the cross-session store (`HH_BURNER_KEYPAIR_JSON` in the git-ignored repo-root `.env`, optionally also the user env var) — never from the repo.
**Tech Stack:** PowerShell 5.1 (repo root), WSL `Ubuntu-24.04` (`program/scripts/wsl-deploy.sh`), Solana devnet, `gh` CLI, pnpm workspace scripts.
**Source spec:** docs/superpowers/specs/2026-11-26-hidden-hand-design.md

**Spike clock and decision rule (hard):**
- When the orchestrator dispatches `program:1` it writes `Build started: <UTC ISO time>` to `docs/spike/clock.md` and commits it (`chore: spike clock`). "T+2 h" means two hours after that time.
- At the spike pause the orchestrator reports the `(a)`, `(b)`, `(c)`, `(f)` lines and the user picks by this rule. All three of `(a)`, `(b)`, `(c)` PASS → keep `manifest.json`. Any of them FAIL, or `docs/spike/spike-result.md` missing, at T+2 h → the commit-reveal fallback, never revisited. A FAIL before T+2 h allows exactly one re-run of Task 14 inside the window. The `(f)` line is informational (it checks the fallback's VRF path on devnet-as).
- **The switch is a merge, not a copy.** A copy would reset every finished task to `pending`. Run from PowerShell at the repo root: `node -e "const fs=require('fs');const p='docs/superpowers/';const cur=JSON.parse(fs.readFileSync(p+'manifest.json','utf8'));const fb=JSON.parse(fs.readFileSync(p+'manifest-fallback.json','utf8'));const st=new Map(cur.tasks.map(t=>[t.id,t.status]));for(const t of fb.tasks){if(st.has(t.id))t.status=st.get(t.id)}fs.writeFileSync(p+'manifest.json',JSON.stringify(fb,null,2)+String.fromCharCode(10));console.log('MERGED')"` (Expected: `MERGED`). It keeps the live `status` of every task in both files and takes the fallback's DAG: `program:20` and `client:21` are added, and `bots:7`, `gates:15` and `gates:16` depend on both. Then commit (`chore: switch to the commit-reveal fallback manifest`).

### Task 11: Burner wallet into the cross-session store

**Files:**
No repository files change (manifest `allow_empty: true`). The burner lives only in the git-ignored `.env` (and optionally the user env var).

**Depends on:** Task 1
**Effort:** low
**Model tier:** top
**Provides:** `HH_BURNER_KEYPAIR_JSON in the git-ignored repo-root .env (64-number JSON array; optional user env var)`

- [ ] **Step 1: Create the devnet burner (gate-concierge, on the user's "continue")**
      First confirm `.env` is git-ignored (Task 1 adds the `.gitignore`). Run (PowerShell, repo root): `git check-ignore -q .env; $?`. It must print `True`; abort otherwise.
      Then create the key and write it in one command that prints nothing secret (PowerShell, repo root; WSL inherits the repo folder): `wsl -d Ubuntu-24.04 -u root --exec bash -lc 'F=/root/.config/hidden-hand/burner-new.json; mkdir -p /root/.config/hidden-hand; solana-keygen new --no-bip39-passphrase --silent --outfile "$F" && printf "HH_BURNER_KEYPAIR_JSON=%s\n" "$(tr -d " \n\r" < "$F")" >> .env && solana-keygen pubkey "$F"; rm -f "$F"'`. It prints only the burner's **public** key; record that in the gate ledger.
      Rules: never `cat` the key file. Never write `.env` with PowerShell `>>`: PS 5.1 adds a BOM or UTF-16, which breaks both readers. Never paste the secret into chat, a commit or a log. Do not `setx` the variable: `loadBurner` prefers the env var while `wsl-deploy.sh` reads only `.env`, so a stale env var would split them.
- [ ] **Step 2: Run the gate**
      Run (PowerShell, repo root): `git check-ignore -q .env; if ($?) { node -e "const fs=require('fs');const m=fs.existsSync('.env')&&fs.readFileSync('.env','utf8').match(/^HH_BURNER_KEYPAIR_JSON=(.+)$/m);let ok=false;try{const a=JSON.parse(m[1].trim());ok=Array.isArray(a)&&a.length===64}catch(e){}console.log(ok?'BURNER-PRESENT: PASS':'BURNER-PRESENT: FAIL')" } else { 'BURNER-PRESENT: FAIL (.env is not git-ignored)' }`
      Expected: PASS — `BURNER-PRESENT: PASS`
- [ ] **Step 3: Commit (kernel-performed — no agent runs this)**
      Message: `chore(gates): burner wallet stored outside the repo`
